# TinyLED

Сверхлегкая, высокопроизводительная и независимая библиотека для управления адресными светодиодами WS2812B (NeoPixel) на платформах **ESP8266**, **ESP32 (Xtensa)**, **ESP32-C3 (RISC-V)** и **RP2040 (Raspberry Pi Pico)**.

Создана как прямая замена (**drop-in replacement**) библиотеки FastLED для проектов часов, бегущих строк и светодиодных матриц.

---

## Ключевые преимущества

| Параметр | FastLED 3.7+ | TinyLED |
|---|---|---|
| **Размер Flash в прошивке** | ~110 КБ | **~2.2 КБ** (экономия > 105 КБ!) |
| **Динамическая память (Heap)** | `malloc` / динамические структуры | **0 байт** (нулевая аллокация) |
| **Вывод ESP32 / ESP32-C3** | Захват прерываний / RMT драйвер | **Аппаратный RMT** (без задержек Wi-Fi и FreeRTOS) |
| **Вывод RP2040 (Pico)** | Сторонние модули / PIOasm сборка | **Аппаратный PIO** (встроенная микропрограмма, любой GPIO) |
| **Вывод ESP8266** | Прерывания / частые срывы кадра | **IRAM cycle-accurate bitbang** с гарантией таймингов |
| **Лимитер тока** | Да | **Да** (по формуле WS2812B 5V) |
| **Цветокоррекция** | Да | **Да** (`TypicalLEDStrip` 0xFFB0F0) |
| **Два режима работы** | Только контроллер | **Внешний буфер** (для 2+ буферов) или **Шаблонный класс** (со своим буфером) |
| **Совместимость API** | Оригинал | **Полная drop-in совместимость** с базовым API FastLED |

## Архитектура аппаратных драйверов

### 1. ESP8266 (Xtensa lx106, 80 МГц / 160 МГц)
* Прецизионный цикл генерации импульсов на базе `rsr.ccount` (подсчет процессорных тактов).
* Код драйвера размещен в **IRAM** (`IRAM_ATTR`), что полностью исключает задержки от промахов Flash-кэша (SPI cache miss).
* Отключение прерываний (`noInterrupts()`) только на время непосредственной передачи битов кадра (~7.7 мс на 256 диодов). Перед передачей автоматически сбрасывается сторожевой таймер (`ESP.wdtFeed()`).

### 2. ESP32 (Xtensa Dual-Core) и ESP32-C3 (RISC-V Single-Core)
* Полноценная аппаратная генерация сигнала через встроенный модуль **RMT (Remote Control)**.
* Автоматическая поддержка как старых платформ (ESP-IDF 4.x / Arduino 2.x), так и новейших (ESP-IDF 5.x / Arduino 3.x с модулями `<driver/rmt_tx.h>` и `<driver/rmt_encoder.h>`).
* Использование механизма **RMT Translator / Simple Encoder Callback**: перевод байтов в импульсы RMT происходит на лету в прерывании RMT FIFO.
* **Не требует промежуточного буфера в RAM** и не блокирует процессор.
* Прерывания FreeRTOS и Wi-Fi **НЕ отключаются**, что гарантирует стабильную работу NTP, Telegram-бота и Web-сервера без мерцания светодиодов.

### 3. RP2040 (Raspberry Pi Pico / Pico W, Dual Cortex-M0+)
* Аппаратная генерация на базе встроенного сопроцессора **PIO (Programmable I/O)**.
* Микропрограмма генерации таймингов WS2812 (4 инструкции) зашита в машинных кодах прямо в исходники драйвера — **не требует утилиты `pioasm`** и компилируется стандартным компилятором C++ в Arduino IDE и PlatformIO.
* Автоматический захват свободного State Machine на `pio0` или `pio1`.
* Делитель частоты рассчитывается динамически по `clock_get_hz(clk_sys)`, гарантируя идеальные 800 кГц при любой тактовой частоте процессора (даже при разгоне).
* Прерывания не блокируются, CPU не загружен передачей бит.

## Выбор GPIO и аппаратные ограничения платформ

### 1. ESP8266 (Xtensa lx106)
* **Поддерживаемые пины:** **GPIO 0 ... GPIO 15** (управляются быстрыми системными регистрами `W1TS` / `W1TC`).
* **Исключение — GPIO 16 (D0):** Этот пин принадлежит RTC-контроллеру (используется для пробуждения из Deep Sleep). Стандартные регистры GPIO им не управляют, поэтому **GPIO 16 использовать для ленты нельзя**.
* **Пины SPI Flash:** GPIO 6–11 подключены к микросхеме памяти, занимать их нельзя.
* **Пины начальной загрузки (Strapping pins):**
  * GPIO 0 (D3) и GPIO 2 (D4) должны быть HIGH при старте микроконтроллера (подтяжка лентой к GND приведет к входу в режим прошивки).
  * GPIO 15 (D8) должен быть LOW при старте.
* **Рекомендуемые (идеальные) пины:** **GPIO 5 (D1)** и **GPIO 4 (D2)**. Они полностью свободны от системных функций и не влияют на загрузку.

### 2. ESP32 (Xtensa Dual-Core)
* **Аппаратная GPIO Matrix:** Позволяет скоммутировать выходной сигнал RMT на любой пин, поддерживающий работу на ВЫХОД.
* **Исключение — Input-Only пины (GPI):** **GPIO 34, 35, 36 (VP), 39 (VN)** на аппаратном уровне не имеют выходных транзисторов и работают **только на вход**. Их нельзя использовать для управления светодиодами.
* **Пины SPI Flash:** GPIO 6–11.
* **Пины начальной загрузки (Strapping pins):** GPIO 12 (MTDI, выбор напряжения Flash 1.8V/3.3V), GPIO 0, 2, 15.
* **Рекомендуемые (идеальные) пины:** **GPIO 22, 23, 21, 19, 18, 17, 16, 25, 26, 27, 32, 33, 4, 14, 13**.

### 3. ESP32-C3 (RISC-V Single-Core)
* **Аппаратная GPIO Matrix:** Связывает RMT с любым выходным пином контроллера.
* **Пины SPI Flash:** GPIO 12–17.
* **Пины USB CDC/JTAG:** GPIO 18, 19 (при использовании аппаратного USB-Serial для прошивки/отладки их занимать не рекомендуется).
* **Пины начальной загрузки:** GPIO 2, 8, 9 (GPIO 9 — кнопка BOOT).
* **Рекомендуемые (идеальные) пины:** **GPIO 6, 7, 0, 1, 3, 4, 5, 10, 20, 21**.

### 4. RP2040 (Raspberry Pi Pico)
* **Аппаратная гибкость PIO:** State Machine может выводить данные на **абсолютно любой пин от GPIO 0 до GPIO 29**.
* **Рекомендуемые пины:** **GPIO 0 ... GPIO 22, GPIO 26 ... GPIO 28**.
* На плате Raspberry Pi Pico пин **GPIO 25** подключен к встроенному светодиоду, а пины **GPIO 23, 24, 29** используются контроллером питания SMPS и измерением напряжения. Их занимать лентой не рекомендуется.

## Ограничения и рекомендации по количеству светодиодов в ленте

Максимальное число светодиодов, которое может обслужить драйвер на одной линии, определяется 4 независимыми факторами: **архитектурой типов в коде**, **оперативной памятью (RAM)**, **физической скоростью протокола WS2812B (время кадра и FPS)** и **электропитанием**.

### Сводная таблица возможностей платформ

| Платформа | Рекомендуемый максимум (30–60 FPS) | Предел для медленных эффектов (5–15 FPS) | Главный ограничивающий фактор |
|---|---|---|---|
| **ESP8266** | **до 500 – 800 диодов** | **до 1 200 – 1 500 диодов** | Прерывания Wi-Fi и Watchdog |
| **ESP32** | **до 2 000 – 3 000 диодов** | **до 10 000 – 15 000 диодов** | Физика протокола (время передачи) и RAM |
| **ESP32-C3** | **до 2 000 – 3 000 диодов** | **до 6 000 – 8 000 диодов** | Физика протокола (время передачи) и RAM |
| **RP2040** | **до 2 000 – 3 000 диодов** | **до 10 000 – 15 000 диодов** | Физика протокола (время передачи) и RAM |

---

### Подробный разбор факторов

#### 1. Ограничение в коде библиотеки
* Переменная количества диодов (`m_num_leds`) имеет тип `uint16_t`, поэтому архитектурный предел счетчика — **65 535 светодиодов**.
* В функции лимитера мощности `calculate_power_scale` используется 32-битный аккумулятор `sum_mA_x255`, который переполнится только при числе диодов более **~400 000**.
* Код библиотеки не накладывает искусственных ограничений на длину ленты.

#### 2. Физика протокола WS2812B (время кадра и FPS)
Протокол WS2812B строго последовательный и работает на фиксированной скорости 800 кГц:
* **1 бит = 1.25 мкс**
* **1 светодиод (24 бита) = ровно 30 мкс** (0.03 мс)
* Пауза сброса (Latch / Reset) = **~300 мкс** (0.3 мс)

Время передачи одного кадра по одной линии рассчитывается по формуле:
$$T_{\text{frame}} = (N \times 0.03\text{ мс}) + 0.3\text{ мс}$$

* **256 диодов** (матрица 32×8): ~8 мс $\rightarrow$ **до 125 FPS** (идеально плавная анимация).
* **512 диодов**: ~15.7 мс $\rightarrow$ **до 63 FPS** (плавно).
* **1 000 диодов**: ~30.3 мс $\rightarrow$ **~33 FPS** (комфортный кинематографический предел).
* **2 000 диодов**: ~60.3 мс $\rightarrow$ **~16 FPS** (начинается заметная потеря плавности динамических эффектов).
* **5 000 диодов**: ~150 мс $\rightarrow$ **~6.6 FPS** (годится только для статичной подсветки или очень плавных/медленных переливов).

#### 3. Архитектура драйвера и стек Wi-Fi

* **ESP32 и ESP32-C3:**
  * Используется **аппаратный модуль RMT**. Прерывания FreeRTOS и сетевого стека **НЕ отключаются**, процессор не простаивает в цикле задержки.
  * Библиотека **не выделяет промежуточный буфер в RAM** (трансляция RMT-импульсов выполняется на лету в ISR FIFO прямо из исходного массива `CRGB`), поэтому память расходуется только на массив пикселей ($3\text{ байта} \times N$).
  * На ESP32 свободно 200–280 КБ RAM. Даже при 10 000 светодиодов массив займет всего 30 КБ. Ограничением служит только физическая длительность передачи кадра (~300 мс $\rightarrow$ ~3.3 FPS).

* **ESP8266:**
  * Вывод выполняется программным битбэнгингом в IRAM с кратковременным запретом прерываний (`noInterrupts()`).
  * Для 256 диодов прерывания отключаются всего на ~7.7 мс — стек Wi-Fi этого не замечает.
  * Если подключить **1 000 диодов**, прерывания блокируются на ~30 мс на каждый вызов `show()`. При частом вызове это приведет к задержкам ответов Wi-Fi (пинг вырастет, Web/Telegram может лагать) и риску перезагрузки по Software WDT (сторожевой таймер сбрасывается перед передачей, но долгие циклы нежелательны).
  * Для ESP8266 с работающим Wi-Fi практический предел составляет **до 600–800 диодов**.

#### 4. Электропитание и ток (физический аспект)
* При 1 000 диодов пиковый ток на чистом белом цвете достигает **~50–60 Ампер при 5V**.
* Встроенный в библиотеку лимитер тока `setMaxPowerInVoltsAndMilliamps` защитит блок питания и проводку, автоматически масштабируя яркость без изменения цветовой гаммы.
* При длине ленты более 300–500 диодов обязательно требуется дополнительный подвод питания (**power injection**) каждые 1–2 метра ленты, иначе из-за сопротивления медных дорожек возникнет просадка напряжения и светодиоды в конце ленты станут тусклыми и приобретут паразитный красный оттенок.

## Два режима использования

### Режим 1: Работа с внешними буферами (FastLED drop-in)
Идеально подходит для проектов со сложными эффектами переходов (слайды, crossFade, бегущие строки), где используются два или более отдельных буфера:

```cpp
#include <Arduino.h>
#include <FastLED.h> // или #include <TinyLED.h>

#define PIN_LED 5
#define NUM_LEDS 256

CRGB leds[NUM_LEDS];
CRGB ledsNext[NUM_LEDS]; // Второй буфер для эффектов перехода

void setup() {
    FastLED.addLeds<WS2812B, PIN_LED, GRB>(leds, NUM_LEDS).setCorrection(TypicalLEDStrip);
    FastLED.setBrightness(50);
    FastLED.setMaxPowerInVoltsAndMilliamps(5, 2000);
    FastLED.clear();
    FastLED.show();
}

void loop() {
    fill_rainbow(leds, NUM_LEDS, millis() / 20, 7);
    fadeToBlackBy(leds, NUM_LEDS, 20);
    FastLED.show();
    delay(15);
}
```

### Режим 2: Шаблонный класс со встроенным буфером
Максимально простой и компактный вариант для проектов, где не требуются дополнительные буферы:

```cpp
#include <Arduino.h>
#include <TinyLED.h>

#define PIN_LED 5
#define NUM_LEDS 64

TinyLED<PIN_LED, NUM_LEDS, ORDER_GRB> strip;

void setup() {
    strip.setCorrection(Correction::TypicalLEDStrip);
    strip.setMaxPower(5, 1500); // 5 Вольт, 1500 мА
    strip.setBrightness(100);
}

void loop() {
    strip[0] = CRGB::Red;
    strip[1] = CHSV(millis() / 20, 255, 255);
    strip[2] = blend(strip[0], strip[1], 128);
    strip.show();
    delay(20);
}
```

При необходимости класс `TinyLED` также позволяет перенаправлять вывод на внешний буфер вызовом `strip.setLeds(ledsNext);`.
